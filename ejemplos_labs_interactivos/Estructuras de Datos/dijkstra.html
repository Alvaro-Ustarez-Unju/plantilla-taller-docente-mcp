Instrucciones para confeccionar el cuadro en el parcial / examen final:

  1. Paso 0 - Inicialización: Dibujar la Matriz de Costos $C[u,v]$ del grafo con $\infty$ en la diagonal y en pares sin arista. Crear los vectores $D$ y $P$. Para el vértice origen $v_0$, marcar $D[v_0] = 0$ y $P[v_0] = v_0$. Para todos los demás $v$, cargar $D[v] = C[v_0, v]$ y $P[v] = v_0$. Colocar $S = \{v_0\}$.
  2. Columna 1 ($V - S$ inicial): Listar los vértices no resueltos aún.
  3. Columna 2 ($w$ elegido): Mirar el vector $D$ únicamente en las posiciones de los nodos en $V-S$. Seleccionar el vértice con el valor $D$ más chico. Ese es $w$ (en caso de empate, desempatar por el de menor índice).
  4. Columna 3 ($S$ actualizado): Agregar $w$ a $S$. Ahora $S = S \cup \{w\}$. El nodo $w$ ya tiene su camino mínimo garantizado para siempre (se tacha en el vector $D$ para recordar que ya no compite).
  5. Columna 4 ($V - S$ restante): Escribir los vértices que quedan pendientes sin $w$.
  6. Columnas 5 y 6 ($k$ y $\min$): Por cada vértice $k$ del nuevo $V-S$, escribir la cuenta explícita:
    min( D[k] , D[w] + C[w,k] )
    Si el camino pasando por $w$ ($D[w] + C[w,k]$) resulta ser estrictamente menor que la distancia que ya teníamos anotada ($D[k]$), se tacha el valor viejo en $D[k]$, se escribe el nuevo número, y en el vector $P[k]$ se anota $w$ como nuevo predecesor.
  7. Finalización: El proceso termina cuando $V - S = \emptyset$. Para reconstruir el camino hacia cualquier nodo, se arranca en el destino y se viaja hacia atrás consultando $P$.
Respetando directivas de cátedra: struct, arreglos estáticos, sin <vector>, sin <stack>, sin class. Lenguaje C++ 
#define MAX_NODOS 10
#define INFINITO 99999

struct Grafo {
    int n; // Cantidad de vertices
    int C[MAX_NODOS][MAX_NODOS]; // Matriz de Costos
};

// Algoritmo de Dijkstra paso a paso
void Dijkstra(const Grafo& g, int origen, int D[], int P[]) {
    bool S[MAX_NODOS]; // true si el nodo ya pertenece a S
    int i, step, w, k, min_dist;

    // 1. Inicializacion
    for (i = 1; i <= g.n; i++) {
        S[i] = false;
        D[i] = g.C[origen][i];
        P[i] = origen;
    }

    D[origen] = 0;
    S[origen] = true; // S = {origen}

    // 2. Iteraciones principales (hasta procesar todos los vertices)
    for (step = 1; step < g.n; step++) {
        // Seleccionar w en V - S con menor D[w]
        min_dist = INFINITO;
        w = -1;
        for (i = 1; i <= g.n; i++) {
            if (!S[i] && D[i] < min_dist) {
                min_dist = D[i];
                w = i;
            }
        }

        if (w == -1 || min_dist == INFINITO) break; // Nodos inalcanzables

        // Agregar w a S
        S[w] = true;

        // Relajar para cada k en V - S
        for (k = 1; k <= g.n; k++) {
            if (!S[k] && g.C[w][k] < INFINITO) {
                if (D[w] + g.C[w][k] < D[k]) {
                    D[k] = D[w] + g.C[w][k];
                    P[k] = w; // Actualizar predecesor
                }
            }
        }
    }
}

¿Por qué Dijkstra falla si existen aristas con pesos negativos?

Dijkstra es un algoritmo voraz (greedy). Da por seguro que una vez que un nodo $w$ es incorporado al conjunto $S$, su distancia $D[w]$ es la mínima definitiva y jamás podrá ser reducida. Si hubiera aristas negativas, un camino posterior más largo en cantidad de aristas pero con suma negativa podría batir ese costo, violando la premisa. Ante aristas negativas se debe emplear el algoritmo de Bellman-Ford o Floyd-Warshall.

¿Cuál es la complejidad temporal del algoritmo?

Con matrices de adyacencia y búsqueda lineal del mínimo (versión clásica de pizarra de la cátedra): $O(|V|^2)$. Con listas de adyacencia y cola de prioridad (min-heap): $O((|V| + |E|) \log |V|)$.

¿Qué papel cumple el vector P en la práctica?

El vector $P$ almacena el árbol de caminos mínimos enraizado en el origen. Para saber la ruta completa hasta un destino $d$, se hace un recorrido hacia atrás: $d \leftarrow P[d] \leftarrow P[P[d]] \dots$ hasta llegar al nodo origen.

💡 Guía de las Columnas del Cuadro

1. Columna V - S (Previa):

Muestra el conjunto de vértices que todavía no tienen su costo cerrado ni están en S. De aquí saldrá el próximo nodo a congelar.

2. Columna w:

Es el vértice elegido dentro de (V - S) que presenta el valor más bajo en el vector D. Se declara como camino mínimo definitivo.

3. Columna S:

Es el conjunto solución acumulado. Se actualiza sumando el nuevo w: S ← S ∪ {w}.

4. Columna V - S (Posterior):

Conjunto de nodos que quedan pendientes tras remover a w. Estos vértices serán los candidatos 'k' a ser evaluados.

5. Columna k:

Cada vértice individual perteneciente al nuevo V - S.

6. Columna min (D[k] ; D[w] + C[w,k]):

Compara si la distancia que ya tenía 'k' es mejor que ir hasta 'w' y luego recorrer la arista (w,k). Si la nueva opción es menor, se actualiza el vector D y se anota w en P[k].
