Cómo Convertir Listas Dinámicas en Otras Estructuras

La Lista Dinámica es la estructura lineal suprema y de acceso abierto. Toda Pila, Cola, Bicola o Lista Circular no es más que una especialización restringida de la misma. Aprendé qué operaciones conservar, cuáles prohibir y cómo reconfigurar los punteros para no equivocarte nunca en un examen.

👨‍🏫

Palabras del Profesor: "El Principio de Restricción Disciplinaria"

"Estimados alumnos: En los exámenes parciales y finales libres, el error más grave no es equivocarse de sintaxis, sino violar la abstracción del TAD. Una Pila no es un archivo de acceso aleatorio; una Cola no permite meter elementos en el medio. Cuando les pedimos diseñar un TAD Pila o Cola a partir del concepto de Lista Enlazada, lo que evaluamos es su capacidad de amputar las libertades innecesarias para garantizar por contrato la disciplina de acceso (LIFO o FIFO)."

🔄 Selector de Transformaciones Dinámicas

Seleccioná la estructura de destino para ver la receta exacta de conversión desde una Lista Dinámica.

📚 De Lista Simple Dinámica → Pila Dinámica
Disciplina LIFO 1 Puntero (TOPE) Acceso O(1)

La Pila es la estructura más restringida: únicamente se inserta y extrae por el mismo extremo superior. Se aprovecha que la cabeza de la lista simple ofrece inserción y borrado en tiempo constante \(O(1)\).

✅ Operaciones que se MANTIENEN

  • InsertarPrincipio → Apilar (Push) Crea nodo y enlaza: nuevo->sig = TOPE; TOPE = nuevo;. Complejidad \(O(1)\).
  • EliminarPrincipio → Desapilar (Pop) Desengancha y libera el tope: TOPE = TOPE->sig; delete aux;. Complejidad \(O(1)\).
  • ListaVacia → PilaVacia Condición exacta: return (TOPE == NULL);.
  • CrearLista → CrearPila Inicializa el único puntero: TOPE = NULL;.

❌ Operaciones que se DEBEN QUITAR

  • InsertarFinal / EliminarFinal ¡TERMINANTEMENTE PROHIBIDAS! Una pila no permite interacción por la base.
  • InsertarOrdenado / En Posición Viola la disciplina temporal LIFO. El orden lo define la cronología de llegada, no el valor de la clave.
  • EliminarValor / EliminarEnMedio No podés extraer un elemento que está debajo sin desapilar previamente los que están por encima.

⚠️ Punteros y Metadatos Clave

  • Puntero de Acceso: Se renombra lista a TOPE o pila. Solo existe UN puntero de control.
  • Fondo de la Pila: El último nodo del fondo siempre apunta a NULL de manera natural.
  • Nueva Operación Clave: TopePila(pila, &valor) para inspeccionar el elemento superior sin destruirlo.
Comparativa de Código C++ 
// EN LISTA SIMPLE DINAMICA:
void InsertarPrincipio(tlistaS &lista, int valor) {
    tlistaS nuevo = new lsd_tnodo{valor, lista};
    lista = nuevo;
}

// SE CONVIERTE EN TAD PILA DINAMICA:
void Apilar(tpila &tope, int valor) {
    tpila nuevo = new pila_tnodo;
    nuevo->elem = valor;
    nuevo->sig = tope;  // El nuevo nodo se apoya sobre el tope actual
    tope = nuevo;       // El tope asciende al nuevo nodo
}
🚨
Trampa de Examen - Pila Vacía (Underflow):

Antes de desapilar, es obligatorio verificar if (PilaVacia(p)). Intentar hacer aux = TOPE; TOPE = TOPE->sig; con TOPE == NULL producirá un segmentation fault que te costará el punto práctico.

🚶 De Lista Simple Dinámica → Cola Simple (FIFO)
Disciplina FIFO 2 Punteros (FRENTE y FINAL) Ambas O(1)

La Cola atiende por un extremo y despacha por el opuesto. En una lista simple común, insertar al final costaba \(O(n)\) por tener que recorrer hasta encontrar NULL. Para convertirla en Cola eficiente, es obligatorio agregar un segundo puntero: FINAL.

✅ Operaciones que se MANTIENEN

  • InsertarFinal → Encolar (Push_Back) Se conecta al nodo apuntado por FINAL en \(O(1)\): co.final->sig = nuevo; co.final = nuevo;.
  • EliminarPrincipio → Desencolar (Pop_Front) Sale el primero apuntado por FRENTE: co.frente = co.frente->sig;. Complejidad \(O(1)\).
  • ColaVacia return (co.frente == NULL);.

❌ Operaciones que se DEBEN QUITAR

  • InsertarPrincipio ¡PROHIBIDO! Sería "colarse" al frente de la fila, destruyendo el principio FIFO.
  • EliminarFinal ¡PROHIBIDO! No se puede retirar al último recién llegado.
  • Cualquier Inserción/Borrado Intermedio En una cola solo existen el primero (atención) y el último (ingreso).

⚠️ Modificación de Estructura de Control

  • De 1 Puntero → A un Registro de Control: Ya no se usa tlista lista. Se define un struct tcola { tnodo* frente; tnodo* final; };.
  • Sincronización Crítica: Al insertar el 1° elemento, frente = final = nuevo. Al quitar el último, frente = final = NULL.
Diferencia Estructural C++ 
// ESTRUCTURA DE CONTROL PARA COLA:
struct tcola {
    nodo* frente;  // Por donde se extrae O(1)
    nodo* final;   // Por donde se inserta O(1)
};

void Encolar(tcola &co, int valor) {
    nodo* nuevo = new nodo{valor, NULL};
    if (co.frente == NULL) {
        co.frente = co.final = nuevo; // Caso cola vacía
    } else {
        co.final->sig = nuevo;        // El ex-último apunta al nuevo
        co.final = nuevo;             // El puntero final avanza
    }
}
⚠️
Peligro de Examen - Puntero Huérfano (Dangling Pointer):

Al desencolar el último elemento de la cola, si hacés frente = frente->sig;, frente queda en NULL pero final queda apuntando a la memoria liberada por delete. ¡Debés hacer if (frente == NULL) final = NULL;!

🔄 De Lista Simple → Cola Dinámica Circular
Anillo Dinámico Cero NULL final->sig = frente

En la Cola Dinámica Circular, el puntero sig del nodo final nunca apunta a NULL, sino que vuelve a apuntar a frente. Esto crea un anillo infinito cerrado con disciplina FIFO.

✅ Operaciones que se MANTIENEN

  • Encolar y Desencolar Conserva los nombres de la cola simple, pero ajusta los enlaces para mantener cerrado el ciclo circular.
  • ColaVacia return (co.frente == NULL);.

❌ Operaciones que se DEBEN QUITAR

  • Bucle while(p != NULL) ¡JAMÁS! En una cola circular, un bucle que busque NULL causará un bucle infinito que colgará la computadora.
  • Acceso a posiciones intermedias Continúa prohibido al ser una cola estricta.

⚠️ Ajustes Circulares Fundamentales

  • Al Encolar: co.final->sig = nuevo; co.final = nuevo; nuevo->sig = co.frente;.
  • Al Desencolar: co.frente = co.frente->sig; co.final->sig = co.frente; (el final actualiza su enlace hacia el nuevo frente).
  • Para Mostrar / Recorrer: Se usa estructura do { ... p = p->sig; } while(p != co.frente);.
↔️ De Lista Doble → Bicola Dinámica (Deque)
Doble Fin (Deque) Nodo Doble (sig, ant) Ambos Extremos O(1)

Una Bicola (Doble Cola) permite insertar y eliminar por ambos extremos (Frente y Final), pero prohíbe el acceso a cualquier posición intermedia. Se construye típicamente sobre una Lista Doblemente Enlazada para que eliminar al final sea \(O(1)\).

✅ Operaciones que se MANTIENEN

  • InsertarPrincipio → EncolarFrente Inserta por el frente de la bicola en \(O(1)\).
  • InsertarFinal → EncolarFinal Inserta por el final en \(O(1)\) gracias al puntero final.
  • EliminarPrincipio → DesencolarFrente Extrae por el extremo delantero en \(O(1)\).
  • EliminarFinal → DesencolarFinal Extrae por el extremo posterior en \(O(1)\) (gracias a p->ant del nodo doble).

❌ Operaciones que se DEBEN QUITAR

  • InsertarOrdenado / En Posición K Completamente prohibido. Toda inserción va a un extremo.
  • EliminarAntesDe / EliminarDespuesDe Elimina la capacidad de manipular elementos internos.
  • Búsqueda y Modificación Interna El usuario del TAD solo ve el frente y el final.

⚠️ ¿Por qué exige Nodos Dobles?

  • Eliminar al Final en O(1): En una lista simple con puntero final, eliminar al final te obliga a recorrer todo el camino para encontrar el penúltimo (\(O(n)\)). Con enlace doble, el penúltimo es directamente final->ant (\(O(1)\)).
⭕ De Lista Simple Abierta → Lista Circular Simple (LCS)
Anillo Cerrado Sin NULL Caso Ejercicio 3 Examen

Se mantiene la capacidad de inserción ordenada y eliminaciones relativas ("antes de", "después de"), pero el último nodo debe reconectarse siempre al nodo INICIO en lugar de tener sig = NULL.

✅ Operaciones que se MANTIENEN (con adaptación)

  • InsertarOrdenado Si el nuevo valor es menor al primer nodo, ¡hay que recorrer hasta el último nodo para que su enlace apunte al nuevo inicio!
  • EliminarDespuesDe(valorRef) Localiza el nodo referencia y desconecta su siguiente en el circuito.
  • EliminarAntesDe(valorRef) Requiere recorrer todo el ciclo hasta encontrar el nodo cuyo sig->sig == ref.

❌ Lo que DEBES QUITAR / CAMBIAR

  • Asignar NULL al crear nodos En el caso de lista vacía, el primer nodo hace nuevo->sig = nuevo;. ¡Nunca NULL!
  • Condición de parada while(p != NULL) Reemplazar por do { ... } while(p != inicio); o while(p->sig != inicio).

⚠️ Caso Crítico de Examen

  • Actualizar el Último Nodo: Si insertás o eliminás el elemento apuntado por INICIO, es obligatorio actualizar el puntero sig del último nodo del anillo. Si no lo hacés, la lista se rompe.
♾️ De Lista Doble Abierta → Lista Circular Doble (LCDE)
Doble Anillo INICIO->ant = ULTIMO ULTIMO->sig = INICIO

Es la estructura lineal dinámica de máxima eficiencia y complejidad de punteros. Como INICIO->ant da acceso directo al último nodo en \(O(1)\), no hace falta un puntero auxiliar FIN.

✅ Operaciones que se MANTIENEN

  • Inserción y Eliminación en Extremos en O(1) Insertar al final es simplemente insertar antes de INICIO (entre INICIO->ant e INICIO).
  • EliminarAntesDe(ref) en O(1) Acceso directo a su predecesor mediante ref->ant. Sin recorrer.

❌ Lo que se ELIMINA

  • Puntero de Control FIN Redundante: inicio->ant es el fin.
  • Verificaciones if(p->ant == NULL) / if(p->sig == NULL) Nunca hay punteros nulos en el anillo. Todo nodo tiene predecesor y sucesor válidos.

⚠️ Cuatro Enlaces por Operación

  • Reconexión Cuádruple: Toda inserción o eliminación intermedia requiere actualizar rigurosamente 4 enlaces bidireccionales en el orden correcto para no desreferenciar memoria liberada.
🛡️ De Lista Simple → Lista con Nodo Cabecera / Centinela
Nodo Ficticio Permanente Cero Casos Especiales CAB Jamás Cambia

Se introduce un nodo dummy (centinela) al principio que no almacena información de usuario. Su función es puramente estructural para que la cabeza de los datos siempre tenga un nodo predecesor físico.

✅ Todas las Operaciones de Lista se Conservan

  • InsertarPrincipio → InsertarDespuesDe(CAB) El primer dato real se coloca inmediatamente después del centinela.
  • EliminarPrincipio → EliminarDespuesDe(CAB) Elimina CAB->sig sin tocar la dirección de CAB.
  • InsertarOrdenado Simplificado No hay if (valor < inicio->info). Todo valor va siempre después de algún nodo existente.

❌ Lo que se ELIMINA

  • Paso por Referencia de la Cabecera (&lista) Como el puntero CAB nunca cambia de dirección tras su creación, las funciones de inserción y borrado pueden recibir CAB por valor.
  • Casos especiales de lista vacía en bucles Desaparecen las bifurcaciones condicionales que complican el código.

⚠️ Responsabilidad de Memoria

  • Destrucción en Dos Fases: Primero vaciar los nodos de datos con Vaciar(cab) y luego ejecutar delete cab; para liberar el centinela.

🏆 Decálogo de Oro del Profesor para Rendir el Examen

10 mandamientos técnicos innegociables para aprobar los ejercicios prácticos y coloquios de la cátedra.

1

Punteros por Referencia (&)

Si la función puede modificar la variable cabecera externa (ej: inicio = nuevo;), el parámetro DEBE llevar &: void Insertar(tnodo* &inicio). Si lo omitís, se modifica una copia local y la lista en el main queda vacía.

2

El "delete" Obligatorio

Todo nodo desvinculado con aux = inicio; inicio = inicio->sig; debe ser destruido con delete aux;. En C++, la pérdida de memoria (memory leak) resta puntos directamente en la corrección.

3

Evitar el Segmentation Fault

Antes de escribir p->sig->elem, es obligatorio validar if (p != NULL && p->sig != NULL). La evaluación perezosa (short-circuit) en C++ evita consultar campos de punteros nulos.

4

Cierre del Anillo Circular

En listas y colas circulares, el nodo nuevo aislado en lista vacía debe hacer: nuevo->sig = nuevo;. Jamás asignes NULL en una estructura circular.

5

Cola Vacía: Sincronizar Final

Cuando la cola queda con 0 elementos al desencolar (frente == NULL), no olvides asignar final = NULL; para evitar que final quede como puntero descolgado (dangling pointer).

6

Bucle de Lista Circular

Nunca uses while(p != NULL) en una lista circular. El recorrido estándar es do { p = p->sig; } while(p != inicio); para asegurar que procese todos los nodos y no se quede en bucle eterno.

7

Respetar la Disciplina del TAD

Si en el examen te piden resolver un problema con una Pila, no podés recorrerla con un puntero auxiliar. Tenés que usar exclusivamente Apilar, Desapilar y una pila auxiliar.

8

Nodo Centinela Fijo

En listas con cabecera (centinela), el puntero CAB nunca avanza ni cambia de dirección en memoria; siempre apunta al nodo ficticio inicial. Los datos arrancan en CAB->sig.

9

Reconexión Cuádruple en Dobles

En listas doblemente enlazadas, cada inserción intermedia cambia 4 punteros: nuevo->sig, nuevo->ant, ant->sig y sig->ant. Conectá siempre primero el nodo nuevo hacia los existentes antes de romper enlaces previos.

10

Justificar Complejidades

En el coloquio oral te preguntarán: "¿Por qué eliminar antes de X es O(1) en lista doble pero O(n) en simple?" Respondé con precisión: en la doble el predecesor es X->ant; en la simple hay que recorrer desde el inicio para hallarlo.
